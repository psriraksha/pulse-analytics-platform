# Deploying Pulse

The frontend and backend deploy to **two different hosts** because the backend
uses Socket.io (persistent WebSocket connections) and Redis, which Vercel's
serverless functions don't support. Vercel is great for the React frontend;
the backend needs a host that runs a long-lived Node process (Render, Railway,
Fly.io, etc.). These steps use Render.

## 0. Provision the databases

- **MongoDB**: create a free cluster at https://www.mongodb.com/cloud/atlas,
  add a database user, allow network access from anywhere (0.0.0.0/0), and
  copy the connection string.
- **Redis**: create a free instance at https://upstash.com (or use Render's
  managed Redis) and copy the connection URL.

## 1. Backend → Render

```bash
cd saas-analytics/backend
git init && git add . && git commit -m "backend"
git remote add origin https://github.com/<you>/pulse-backend.git
git push -u origin main
```

In the Render dashboard: **New → Blueprint**, point it at this repo (the
`render.yaml` in the project root configures the service automatically), or
**New → Web Service** manually with:

- Root directory: `backend`
- Build command: `npm install`
- Start command: `npm start`

Set these environment variables (Render prompts for any marked `sync: false`
in `render.yaml`):

| Variable | Value |
|---|---|
| `MONGO_URI` | your Atlas connection string |
| `REDIS_URL` | your Upstash/Redis connection string |
| `JWT_SECRET` | auto-generated by the blueprint, or set your own |
| `CORS_ORIGIN` | your Vercel URL, e.g. `https://pulse-dashboard.vercel.app` |
| `TRACKING_SCRIPT_BASE_URL` | your Render URL, e.g. `https://pulse-backend.onrender.com` |

Deploy. Confirm it's up: `curl https://pulse-backend.onrender.com/health`
should return `{"status":"ok",...}`.

## 2. Frontend → Vercel

```bash
npm i -g vercel
cd saas-analytics/frontend
vercel login
vercel
```

Answer the prompts (link as a new project, framework auto-detects as Vite).
Then set the API URL and deploy to production:

```bash
vercel env add VITE_API_URL production
# paste: https://pulse-backend.onrender.com

vercel --prod
```

The included `frontend/vercel.json` adds an SPA rewrite so refreshing
`/dashboard` or `/live` doesn't 404.

## 3. Close the loop

Go back to Render and double check `CORS_ORIGIN` matches your live Vercel
URL exactly (no trailing slash), then trigger a redeploy so the auth,
sites, dashboard, and export routes accept requests from it.

## 4. Seed demo data (optional)

Run once, locally, pointed at your production databases:

```bash
cd backend
MONGO_URI="<atlas-uri>" REDIS_URL="<redis-uri>" node scripts/seed.js
```

This creates a demo account (`demo@example.com` / `demo1234`) with 30 days
of synthetic traffic so the dashboard isn't empty on first login.

## 5. Verify end-to-end

1. Visit your Vercel URL, sign up or log in with the demo account.
2. Go to **Setup**, copy the tracking snippet.
3. Paste it into any test HTML page and open it in a browser.
4. Watch the **Live** tab — active visitor count and the event feed should
   update within a few seconds (this is the part that requires the backend
   to support WebSockets, which is why it isn't on Vercel).
